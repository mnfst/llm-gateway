Add `private_docs` as a specificity category for deterministic routing. Conversations containing private-document signals (HIPAA, attorney-client, medical records, confidential documents, financial statements, etc.) can now be pinned to a specific route — e.g. a Privatemode-compatible OpenAI endpoint at `https://api.privatemode.ai/v1` — via the existing specificity override assignment. Detection uses weighted keyword anchors so a single distinctive term (e.g. "HIPAA") outscores generic verbs ("analyze") that also fire the data_analysis dimension. The `x-manifest-specificity: private_docs` header can also force the category with confidence 1.0. Removed `hipaa`/`gdpr` from the `domainSpecificity` keyword set to prevent cross-dimension overlap. Added financial/retirement document keywords (401k, IRA, Roth IRA, HSA, FSA, 529, 1099, W-2, brokerage/mortgage/bank statements, pension) using compound phrases (e.g. "my hsa", "hsa statement", "401k statement", "w-2 form", "my 1099") to avoid false positives on general-knowledge questions like "explain Roth IRA income limits" or "what is a W-2".

Fix: add the missing `private_docs` `StageDef` to `SPECIFICITY_STAGES` in `packages/frontend/src/services/providers.ts` (step 10, "Private Documents") and its `SPECIFICITY_ICONS` entry in `RoutingSpecificitySection.tsx` — without the stage definition the category was accepted by the API but invisible in the Routing page and message-log filters, and a saved `private_docs` assignment was orphaned (hidden). Adds a frontend parity test (`tests/services/specificity-stages.test.ts`) and a backend static check (`specificity-ui-stages.spec.ts`) asserting every `SPECIFICITY_CATEGORIES` entry has a `SPECIFICITY_STAGES` stage, so a future category can't land the backend without the UI.

Fix: demote the bare single-word `private_docs` keywords that collide with coding / science vocabulary (`phi`, `sox`, `msa`, `nda`, `soc2`, `confidential`, `diagnosis`, `prescription`, `testimony`) from weight 3 to a sub-threshold 0.5 in `specificity-weights.ts`. Previously each matched whole-word at weight 3 against an activation threshold of 1.0, so a single occurrence — "compute the phi coefficient", "write a sox script", "this document is confidential" — flipped routing to the privacy-preserving provider at confidence 1.0. Now a single collisioning token can't activate the category on its own; it only reinforces a genuine private anchor. The unambiguous privacy acronyms (`hipaa`, `pii`, `gdpr`, `ccpa`, `pdpa`) stay at weight 3 so prompts like "extract pii from this csv" still route correctly with no second signal. Adds false-positive regression tests for the collision vocabulary, positive controls that demoted tokens still work when paired, and weight assertions pinning the sub-threshold tier.

Fix: sync `PRIVATE_DOCS_KEYWORDS` with `KEYWORD_WEIGHTS` — six weight-3 anchors (`medical files`, `health files`, `health document`, `529 statement`, `confidential agreement`, `discovery documents`) previously had no keyword-list entry so could never match, and `credit report` / `my 401k` were keyworded but unweighted (running at the default 1.0 instead of the anchor tier 3). The two lists now agree.
